## 2. P0 — Deux produits affichent le RCP d'un autre médicament

`scripts/build-pdf-sections.js:166-167`

```js
const nomLocal = (url) =>
  path.join(CACHE, path.basename(new URL(url).pathname).replace(/[^\w.-]/g, '_'));
```

Le cache disque est indexé sur le **seul nom de fichier**, alors que l'EMA range ses PDF par
principe actif. Deux URL distinctes retombent sur le même fichier ; le premier téléchargé
gagne, le second est lu à sa place. Vérifié en base :

| CIS | Dénomination BDPM | Rubrique 1 réellement stockée |
|---|---|---|
| `62474215` | **EFAVIRENZ**/EMTRICITABINE/TENOFOVIR DISOPROXIL MYLAN | Emtricitabine/Ténofovir disoproxil Mylan |
| `66747729` | TENOFOVIR DISOPROXIL ZENTIVA 245 mg | Emtricitabine/Ténofovir disoproxil Zentiva |

Pour `62474215`, l'efavirenz — un INNTI dont le profil d'interactions commande toute la
rubrique 4.5 — **a disparu du RCP affiché**. Pour `66747729`, c'est l'inverse : une
association bithérapie est servie pour un principe actif seul. Posologie, contre-indications
et interactions diffèrent dans les deux sens.

C'est exactement l'erreur que `choisirBloc()` a été écrite pour empêcher, contournée un étage
plus bas.

**Correctif :** faire entrer le chemin complet dans le nom local — l'empreinte de l'URL suffit
et supprime toute la classe de bugs.

```js
const nomLocal = (url) =>
  path.join(CACHE, `${createHash('sha1').update(url).digest('hex').slice(0, 16)}.pdf`);
```

Puis rejouer les CIS concernés (`--all` sur les quatre, ou vider `.cache/pdf`). Un contrôle
permanent vaut mieux qu'une correction ponctuelle : `choisirBloc()` connaît déjà la
dénomination attendue et le score de recouvrement — **le rejeter en dessous d'un seuil**
transformerait cette classe de fautes en `echec` visible plutôt qu'en texte plausible.

## 3. P0 — La recherche par principe actif ne rend pas ce qu'elle promet

Le README pose la promesse : « Chercher *paracétamol* remonte DOLIPRANE et DAFALGAN : ces
produits ne portent pas le terme dans leur nom, et c'est le comportement attendu. » C'est le
seul avantage réel sur le site officiel. Mesuré :

| Requête | Onglet « Tous » | Onglet « Principe actif » | Introuvables en base |
|---|---|---|---|
| `paracetamol` | 60 marque / **0 substance** | 60, tous nommés « PARACETAMOL … » | **105 CIS** |
| `ibuprofene` | 59 marque / **1 substance** | — | 44 CIS |
| `levothyroxine` | 0 / 60 | — | 67 CIS |

DOLIPRANE, ACTIFED RHUME, ACTRON, CLARADOL, CEFALINE HAUTH : **inaccessibles sur les deux
onglets**. Deux causes cumulées dans `src/search.js` :

1. **Un `LIMIT 60` partagé** (ligne 101) entre les deux familles. 60 spécialités portent
   « paracetamol » dans leur nom : elles consomment tous les créneaux.
2. **Le rang est calculé sur la dénomination pour *toutes* les lignes** (lignes 90-94), y
   compris celles trouvées par substance. Une ligne « active » ne peut donc jamais faire mieux
   que `rank = 2`. C'est pourquoi l'onglet « Principe actif », qui pourtant écarte les
   `brand_hits`, remonte quand même PARACETAMOL EG et PARACETAMOL TEVA en tête : **le tri
   privilégie précisément les produits pour lesquels la recherche par substance
   n'apportait rien.**

**Correctif :** deux quotas distincts (`LIMIT` par `match_type`, via `row_number()`), et un
rang propre aux lignes « active » — correspondance exacte de substance d'abord. Le SQL reste
une seule requête.

Tant que ce point n'est pas corrigé, « plus flexible » est hors d'atteinte : la souplesse
déjà écrite n'arrive pas jusqu'à l'écran.

## 4. Performance — le gain qui reste

Le SQL est rapide (1-26 ms). Ce qui est lourd, c'est ce qui part sur le réseau.

**Aucune compression HTTP.** Mesuré sur `/product/66367812` :

| | Octets |
|---|---|
| Tel que servi aujourd'hui | **850 583** |
| `gzip -9` | **137 996** (−84 %) |

Les fiches transportent 100 à 850 Ko de HTML — toutes les rubriques sont rendues dans le
document même quand les `<details>` sont fermés. Sur une connexion de comptoir, c'est le poste
dominant, loin devant la base. Trois lignes :

```js
import compression from 'compression';
app.use(compression());
```

Deux suites possibles, dans cet ordre de rendement :

- **Charger les rubriques à la demande.** L'API `/api/product/:cis/documents` existe déjà et
  `docs.rcp_sections` est indexée par CIS : la fiche peut n'embarquer que son plan et aller
  chercher le corps d'une rubrique à l'ouverture. La page tombe sous 30 Ko.
- `Cache-Control` sur les fiches produit. Les données bougent une fois par mois ; il n'y a
  aucune raison de recalculer une fiche à chaque visite.

## 5. Flexibilité — ce qui manque

**Aucune tolérance aux fautes de frappe.** La recherche est exclusivement
`LIKE '%terme%'`. « paracetmol », « ibuprofen », « levotyrox » rendent zéro résultat.
`pg_trgm` est pourtant installé et les index GIN sont là : `similarity()` et l'opérateur `%`
sont disponibles gratuitement. Un repli sur la similarité trigramme quand l'exact ne rend rien
est la fonctionnalité la plus rentable du lot — c'est l'attente n° 1 sur un champ de
recherche, et l'infrastructure est déjà payée.

**L'index plein texte est construit mais jamais interrogé.** `idx_sections_texte_fts` couvre
492 214 rubriques. Le README en fait la question que le site officiel ne sait pas poser :

```sql
SELECT code_cis FROM docs.rcp_sections
WHERE numero = '4.3'
  AND to_tsvector('french', texte) @@ plainto_tsquery('french', 'insuffisance rénale');
```

**Aucune route ne l'expose.** C'est la fonctionnalité la plus distinctive du projet, à
quelques dizaines de lignes de l'utilisateur : l'index existe, les données sont là, il manque
le point d'entrée.

**Autres angles absents :** recherche par CIP13 (le code que le pharmacien a sous les yeux),
par titulaire, par groupe générique. Le premier est un simple `WHERE code_cip13 = $1` sur une
table déjà indexée.

## 6. Chaîne PDF européenne — au-delà du P0

Elle fonctionne : 2 052 CIS sur 2 101, 98 % de RCP complets. Les réserves portent sur la
reprise, pas sur le résultat.

- **L'incrémental télécharge avant de comparer** (`build-pdf-sections.js:273-277`). L'empreinte
  est celle du PDF, il faut donc l'avoir. Cache présent, c'est gratuit ; cache vidé — et il est
  dans `.gitignore`, 922 Mo — c'est un rapatriement complet chez un EMA qui limite le débit.
  Stocker l'`ETag` ou le `Last-Modified` de l'EMA à côté du lien permettrait un `HEAD`
  conditionnel et rendrait le rejeu mensuel trivial.
- **`connu` est indexée sur `code_cis` seul** (ligne 85) alors que la clé primaire de
  `docs.document_parse` est `(code_cis, document_type)`. Les deux lignes d'un CIS s'écrasent.
  Sans conséquence aujourd'hui (même empreinte, même version), mais un RCP réussi et une
  notice en échec feraient sauter les deux au rejeu.
- **Le lien réel est extrait par regex du HTML de `affichageDoc.php`** (ligne 116). Point de
  rupture unique, hors de notre contrôle, sans test. Une évolution de la page BDPM arrête toute
  la chaîne — et la panne se lira « 2 101 spécialités hors périmètre », pas « le scraper est
  cassé ». Un garde-fou (« si plus de 20 % des fiches ne rendent aucun PDF, s'arrêter ») rendrait
  la panne lisible.
- **Les 49 `null` de `liens.json` sont définitifs.** Une AMM republiée ne sera jamais reprise ;
  rien ne les périme.
- **Reste 55 CIS muets**, 6 `echec` et 106 `partiel`. Volume normal, mais aucun suivi ne les
  fait remonter : `npm run diagnostic` est en lecture seule et personne ne le lance.
- **`pdftotext` (poppler) est une dépendance de fait**, déclarée nulle part sauf dans un message
  d'erreur. Sa place est dans le README, à côté de PostgreSQL.

  devient un test, soit il s'en va.
- `AUDIT.md` à supprimer ou archiver : il décrit un état révolu et induira en erreur.

**Code**

- `MIN_LENGTH = 3` en dur dans `public/js/search.js:12`, quand le serveur lit
  `SEARCH_MIN_LENGTH`. Régler la variable désaccorde les deux.
- La CSP autorise `site-assets.fontawesome.com` (`src/middleware.js:10-11`) ; plus aucune vue
  ne charge Font Awesome. Autorisation à retirer.
- Aucune limitation de débit sur `/api/*`. Le `statement_timeout` de 5 s borne chaque requête,
  pas leur nombre.
- Pas de `.env` sur la machine : ça ne tourne que parce que `config.js` retombe sur
  `incidents_json`. À créer depuis `.env.example` avant tout déploiement.
